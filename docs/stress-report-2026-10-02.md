# Перевірка UCPC — 2 жовтня 2026

Перевірено текстову версію для Windows 11 із Mouse4 для додавання скріншота та Mouse5 для відправлення. Модель власника: `gpt-5.6-sol`, аналіз `high`, автоматичний другий запит вимкнений. Акаунт і власна системна інструкція не замінювалися.

## Що змінилося

- Старі стандартні F8/F9 мігрують на Mouse4/Mouse5. Власні й вимкнені бінди та вже зайняті користувачем кнопки зберігаються. Допомога, трей і налаштування показують поточні призначення.
- Запит каталогу моделей не починається під час входу або виходу. Пізній результат попереднього входу відкидається.
- Початок зміни акаунта або виходу скасовує відкладені спроби копіювання старої відповіді. Поточний буфер обміну не очищається.
- Остаточне форматування відповіді зберігає виділений текст, напрям виділення й позицію читання; перевірено також український текст та emoji.
- Виправлено визначення Python, коли `import sys` і `from collections ...` стоять на сусідніх рядках. Раніше регулярний вираз міг прийняти їх за JavaScript.
- Win у мишачих біндах відхиляється з поясненням: справжній Win+Mouse4 відкривав «Пуск». Mouse4/Mouse5 окремо або з Ctrl/Shift працюють; клавіатурні Ctrl+Win залишаються доступними.
- Аудит VS Code підтримує мишачі призначення й не намагається знайти їх у числовій таблиці клавіатурних KeyCode.

Перевірки каталогу, копіювання та виділення спочатку відтворили падіння, а після виправлень пройшли. Конфлікт Win+Mouse4 відтворений справжнім `SendInput`.

## Стиль коду

Стиль задають три окремі механізми:

1. Конкретні правила: прямі цикли, умови, звичайні функції та стандартні контейнери; зрозумілі імена; без зайвих класів, шаблонів, макросів і універсальних обгорток. Необхідний алгоритм, структура даних та продуктивність мають пріоритет над спрощенням запису. Власний парсер вводу потрібен лише за відповідних обмежень.
2. Короткі приклади простого запису для C++, Python, JavaScript і C#. Це приклади стилю, а не готові алгоритми конкретних задач. Приклади в промпті є способом спрямувати модель без навчання її ваг. [OpenAI: приклади в інструкціях](https://developers.openai.com/api/docs/guides/prompt-engineering#few-shot-learning).
3. Локальне форматування завершеного коду: у впізнаних C/C++, Java, C#, JavaScript, TypeScript, Go та Rust відступи по чотири пробіли приводяться до табів; у впізнаному коректному Python блоки приводяться до чотирьох пробілів. Рядкові літерали захищені. Для Python синтаксичне дерево до й після зміни має збігатися. При невпізнаному синтаксисі, некоректних відступах або помилці форматування зберігається оригінал. Неповні й скасовані відповіді не переформатовуються.

Це не fine-tuning і не гарантія певного стилю кожної майбутньої відповіді. Перевірки стилю та правильності розділені: читабельність коду не є доказом правильного алгоритму.

## Справжні запити до моделі

Надсилалися синтетичні зображення з повною умовою, без знімків приватного робочого столу. Використано звичайний шлях `Engine._generate`, поточний акаунт та його інструкцію. Автоматичний другий прохід не вмикався.

| Мова | Задача перевірки | Час генерації | Запуски |
|---|---|---:|---:|
| C++23 | Суми відрізків, 64-бітні значення, до 200000 елементів і запитів | 14,42 с | 5/5 |
| Python | BFS у сітці, до 500×500, недосяжна ціль | 16,28 с | 5/5 |
| JavaScript / Node.js | Найдовша серія однакових значень, до 200000 чисел | 10,56 с | 5/5 |
| C# / .NET 8 | Сума 200000 чисел, довільні роздільники, 64-бітний результат | 5,05 с | 5/5 |

C++ та C# скомпільовано; Python перевірено компілятором Python та запущено; JavaScript запущено Node.js. На великих входах виконання займало менше секунди в цьому середовищі. Усі 20 результатів збіглися з незалежно обчисленими очікуваними відповідями. Найбільший тест C++ повторено з точними межами `n=q=200000` після виправлення генератора тестових даних.

Код також прочитано: C++ використовує простий префіксний масив, Python — стандартний `deque` і прямий BFS, JavaScript — один цикл, C# — стандартне читання й один цикл. Python має чотири пробіли; три інші відповіді — таби. Перші пробні запити виявили недотримання відступів Python і зайвий сканер C#; правила та форматування уточнені, після чого наведений вище повторний прогін пройшов.

Режим F10 додатково перевірено двома справжніми запитами з видимими input/output: неправильний результат визначений як «НЕ ЗБІГАЄТЬСЯ» за 11,24 с, правильний — «ЗБІГАЄТЬСЯ НА ЦЬОМУ ТЕСТІ» за 9,32 с. Модель вказала очікуване значення та не заявила про проходження невидимих тестів.

Чотири нескладні контрольні задачі перевіряють мову, стиль, повноту коду й шлях запиту. Вони не є оцінкою успішності на всіх складних олімпіадних задачах. Java, Go, Rust і TypeScript мають тести форматування, але їхній згенерований код у цьому прогоні не компілювався. Побудова набору з типовими й крайовими випадками відповідає [рекомендаціям OpenAI щодо оцінювання](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

## Автоматичні перевірки

Три повних прогони у нових процесах: **325/325**, **325/325**, **325/325**; приблизно 101–108 с кожен, із `-W error`. Останній прогін включає різні 8-КБ відповіді та перевірку адресата кожного звичайного мишачого кліку. Покриття рядків основних модулів: **91,17% — 2169 із 2379 виконуваних рядків**, 210 залишаються непокритими. Це покриття рядків, не всіх можливих станів програми.

Поза покриттям pytest залишаються, зокрема, частина CLI-обробки аварійного старту, деякі резервні GUI/файлові шляхи, збій запуску native hook або його message loop та частина консервативних відмов форматування. Вхід на чужому ПК і відмова зовнішнього сервісу перевіряються підмінами, а не реальними чужими акаунтами. Повний список рядків є в `data/stress/coverage-final.json`.

Фінальна посилена серія: **6 нових процесів × 19 навантажувальних тестів = 114 успішних сценаріїв**, без помилок, пропусків та попереджень. Часи процесів: 77,334; 76,718; 79,633; 78,710; 79,771; 77,321 с. Перед цією серією також пройшли чотири ранні навантажувальні цикли; їх не додаємо до наведеного нижче навантаження посиленого набору.

Тестові запити, токени й callback у pytest синтетичні; зовнішній сервіс підмінено на мережевій межі. Windows-тести використовують справжні локальні сокети, API Windows, події вводу та вікна. Компіляція й запити до живої моделі винесені в окремі ручні перевірки.

При ранньому прогоні один тест миші вимагав доставки подій за фіксовані 15 мс. Тепер він чекає точні події down/up з обмеженим таймаутом; зайві або пропущені події все ще призводять до падіння. П'ятий ранній навантажувальний прогін зупинився через втрату фокуса тестового редактора: за записаним HWND іншим активним вікном був `ChatGPT.exe`, а не «Пуск» чи UCPC. Після цього окремо виконано 20 нових процесів з обома порядками Ctrl/Win та справжніми боковими кнопками: усі 60 сценаріїв пройшли. У наступній серії клік непризначеною кнопкою пішов у `chrome.exe` після зміни фокуса. Тепер перед такими кліками тест відновлює фокус і курсор та перевіряє HWND під точкою; після клавіатурного бінда фокус усе ще має залишатися в редакторі. Самі фонові призначені кнопки перевіряються глобально, без вимоги фокуса прихованого UCPC. Початкові невдалі звіти збережено в `data/stress/before-focus-diagnostics` і `data/stress/before-cursor-preconditions`, їх не зараховано як успішні.

## VS Code і Windows-збірка

За актуальним [списком Microsoft для Windows](https://raw.githubusercontent.com/microsoft/vscode-docs/main/build/keybindings/doc.keybindings.win.json) та встановленим VS Code 1.140.0: **1261 правило + 92 правила вбудованих розширень, конфліктів зі стандартними біндами UCPC немає**. Власні призначення користувача та сторонніх розширень до цього висновку не входять.

Зібрано `dist/UCPC` з 19 явно перелічених модулів. У замороженому EXE перевірено фактичні Mouse4/Mouse5 та наявність модулів миші й форматування. Дистрибутив містить 217 файлів до додавання маніфесту. Робоча конфігурація, власна інструкція, `.env`, акаунти, скріншоти й журнали не копіюються. Наявні раніше ZIP-архіви цією перевіркою не перезапаковувалися.

EXE перевірено в папці з українськими літерами й пробілами, із порожнім `%LOCALAPPDATA%` та лише Windows у PATH: `--check` і **три `--smoke` поспіль завершилися кодом 0**. Додатковий native probe підтвердив фактичну реєстрацію Ctrl+Win+F1 під час кожного запуску та звільнення після виходу; невдалий запуск mouse hook повертає клавіатурну реєстрацію назад, тому одного нульового exit code недостатньо для цієї перевірки. Перший запуск створив стандартні Mouse4/Mouse5, інструкцію та `.env`, точно рівний порожньому шаблону; файлу акаунта немає. Перед цим самоперевірка тестового інструмента помилково вимагала відсутності `.env` після запуску; очікування уточнено відповідно до штатної ініціалізації програми, власний `.env` не переносився.

## Як повторити

Закрий власний UCPC під час native-тестів і не користуйся клавіатурою/мишею: тестові вікна тимчасово займають фокус.

```powershell
uv run --locked pytest -q -W error
uv run --locked python -m tools.repeat_stress --full-cycles 2 --cycles 10
uv run --locked ruff check ucpc tests tools
uv run --locked python -m tools.audit_shortcuts
uv run --locked --group build python -m tools.build_release
uv run --locked python -m tools.check_release
```

Окремо, з використанням ліміту поточного акаунта та встановленими g++, Node.js і .NET 8 SDK:

```powershell
uv run --locked python -m tools.evaluate_style
```

Технічні звіти зберігаються локально в `data/stress`, `data/style-eval`, `data/shortcut-audit.json` та `data/release-check.json`. Дані цієї ручної оцінки не входять до дистрибутиву.

## Mouse4/Mouse5 у справжніх браузерах і фінальний архів

Після загальних стрес-тестів виконано окрему перевірку видимих Chrome та Edge через Playwright і справжні XBUTTONDOWN/XBUTTONUP Windows. Тестові сторінки мають реальну історію A → B → C. Спочатку без UCPC підтверджено, що Mouse4 переходить назад, а Mouse5 — вперед. Після увімкнення UCPC призначені кнопки більше не доставляються сторінці й не змінюють URL або фокус браузера.

У кожному браузері пройшло 12 наборів по 1–4 кадри: разом **60 справжніх PNG-скріншотів у 24 запитах**. Перевірено колір захопленої тестової сторінки, цілісність PNG, точний порядок зображень у тілі запиту та відсутність кадрів попереднього набору. Зйомка сама нічого не відправляє. Повторна відправка порожньої черги не дублює й не скасовує активний запит; приховування відповіді під час запиту не заважає його завершенню. При призупинених біндах повертається звичайна навігація назад/вперед, після відновлення знову працює зйомка UCPC.
